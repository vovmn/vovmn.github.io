# Схема базы Immunolab

Каноническая схема для новой PostgreSQL находится в `backend/schema.sql`. Обновление уже существующей базы и загрузку опросников выполняет транзакционный скрипт `backend/scripts/init-db.js`.

## Основные сущности

| Таблица | Назначение |
| --- | --- |
| `users` | Пациенты и администраторы |
| `antigens` | Реестр антигенов с уникальными UUID и названиями |
| `user_antigens` | Связи пациентов с назначенными антигенами |
| `refresh_tokens` | Хеши refresh-токенов с датой истечения |
| `body_systems` | Справочник систем организма |
| `questions` | Версионируемые вопросы со стабильным кодом, ветвлением и правилами проверки |
| `answer_options` | Допустимые варианты для вопросов с выбором |
| `user_questionnaire_assignments` | Отдельное назначение опросника пациенту, включая срок, приоритет и жизненный цикл |
| `user_answers` | Ответы, привязанные к конкретному назначению |
| `appointments` | Записи пациента на приём |
| `questionnaire_releases` | Версия, SHA-256 и количество вопросов импортированного набора |
| `schema_migrations` | Применённые версии структуры базы |

## Ключевые правила целостности

- Повторное назначение одной системы разрешено: каждое прохождение имеет собственный `assignment_id`.
- Ответ может принадлежать только тому пациенту, которому принадлежит назначение.
- Выбранный вариант обязан принадлежать тому же вопросу.
- Строка ответа содержит ровно один вид значения либо явный пропуск/ответ «не знаю».
- У активного вопроса обязательно есть стабильный код.
- Старые вопросы архивируются через `active = false`, а не удаляются.
- Статусы назначения согласованы с `started_at`, `completed_at` и `cancelled_at`.
- `updated_at` назначения обновляется триггером базы.
- Для новых пациентов обязательны `username`, хеш пароля, `gender`, `age` и `age_recorded_at`; администраторы могут существовать без пациентских полей.
- `email`, телефон, дата рождения и место жительства пациента необязательны. Возраст хранится вместе с датой фиксации и не подменяет дату рождения.
- При обновлении существующей базы возраст вычисляется из известной даты рождения. Оставшиеся неполные профили требуют исправления администратором и блокируются для назначения/прохождения опросников.
- Связь пациентов и антигенов хранится в `user_antigens`: пациенту можно назначить несколько антигенов, а один антиген — нескольким пациентам.
- Пара `(user_id, antigen_id)` уникальна и не допускает повторного назначения того же антигена тому же пациенту.
- При удалении пользователя или антигена удаляются только соответствующие строки связи.

## Жизненный цикл назначения

```text
pending -> in_progress -> completed
   |            |
   +------------+-> cancelled
```

Завершённое назначение не переиспользуется. Для повторного прохождения создаётся новая запись.

## Версионирование

Текущая версия схемы: `20261031_02`.

Версия опросника берётся из `python/questionnaire.json`. При импорте в `questionnaire_releases` записываются версия, контрольная сумма исходного JSON и количество вопросов. Это позволяет проверить, что сервер использует именно ожидаемый набор.
